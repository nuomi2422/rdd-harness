# 摄影师（photographer/）

> 隔离工作树：`D:\rdd\worktrees\photographer`（分支 `photographer-film`）。
> 主工作树 `D:\rdd\harness\rdd-harness` 里还有别的 AI 在写 experiments/，本目录的改动不落地到那边。

## 这个 AI 干什么

看游戏里那个 AI 在干活 → 拍下来 → 挑出「有事发生」的段落剪成短片 → 删掉占地方的帧序列。

一句话：**不是记录全部，是记录能证明它会干活的那几段。**

## 三个脚本，一条链

| 脚本 | 作用 | 关键判据 |
|---|---|---|
| `film.mjs` | 一轮：检查取景 → 录 N 秒 → 调 cut → 记台账 → 调 patrol 清理 | 目标不可见/距离 > 24/已在录 → 直接不拍 |
| `cut.mjs` | 从一个 take 里挑变化段，切 clip 并拼成 `cut/highlight.mp4` | ffmpeg `scene` 分数 > 0.18；段间重叠合并；总长 ≤ 45s |
| `patrol.mjs` | 采样（`--once`）、常驻（`--loop 60`）、收摊（`--clean`，默认演练，`--apply` 才删） | 目标不可见 / 距离 > 24 / 贴脸 < 1.2 → 记 flags |

## 为什么这么切

- **变化 = 事件。** AI 在挖矿/打架/传送时画面剧烈变化；站着不动、界面挂着时几乎不动。
  用像素变化挑段，比「每 5 秒抽一帧」准得多，也不需要任何模型。
- **宁少不滥。** 总长封顶 45 秒、最多 6 段；挑不出就报错（`no-motion`），不硬凑。
- **删是不可逆的。** `--clean` 默认只打印计划；`film.mjs` 只在成片落盘后才调 `--apply`。

## 已知的坑（都是这轮踩的）

1. ffmpeg 的 `metadata=print:file=` **不能带盘符和空格**（会被当成 filter 选项），必须切到输出目录写相对名。
2. take 目录的 **mtime 不能当「新旧」**：往里写 `cut/` 就刷新了，刚剪完的会永远算新的。
   take 名字里自带开拍时间（`numencam_YYYYMMDD-HHMMSS`），用它。
3. 正则里的 `\d` 在模板字符串里会被吃成 `d` —— 写文件时用 `String.raw`，否则 `/(d{8})/` 永远匹配不上，
   结果是「所有 take 都算超期」直接删光。

## 还没做

- 事件语义：`cut.mjs` 会把段落对到 `patrol.jsonl` / `numencam.jsonl` 里最近的记录，但**必须拍摄当时有人在采样**，
  否则只能对到很远的旧记录（本轮就出现过 7.8 万秒的偏差）。
- 亮度判据：现在靠调用方看帧决定夜视，脚本不自动开（要开就得先能解码像素）。
- 遮挡：相机没有射线检测，贴墙/穿墙只能靠人眼看帧发现。

## 机位经验（这轮踩出来的）

| 场景 | 用什么 | 为什么 |
|---|---|---|
| 草原/开阔地 | ORBIT 6.5 格 / 高 2.2 | 能同时看到它和它在看的东西 |
| 室内/洞穴/窄通道 | BODY（第一人称） | 第三方机位会卡进方块，第一人称至少是它看见的画面 |
| 树林密集 | 先 BODY 试，不行再退 | ORBIT/SHOULDER 会被树叶糊满（连着两轮都这样） |

**BODY 的代价**：看得到它在看什么，看不到它本人。要「体现 agent 能力」的片子，两条腿都要有。

## 第三轮：机位到底该怎么选（读代码读出来的）

`MixinCamera` 里只有 **SHOULDER / CINEMATIC** 会走 `numencam$maxZoom()` —— 也就是原版那套
「8 个角点各打一条射线，被挡就把镜头拉近」。**ORBIT 是直接用 cos/sin 硬算坐标，完全不躲方块**，
所以它在树林/洞穴里必然穿模。

结论（已写进 `film.mjs --auto`）：

| 环境 | 机位 | 原因 |
|---|---|---|
| 密林 / 洞穴 / 室内（biome 含 forest/taiga/jungle/swamp 或 y<62） | **CINEMATIC** distance 6 / height 1.6 | 有射线拉近，贴墙也看得见人 |
| 开阔（草原、河谷、村庄空地） | ORBIT 6.5 / height 2.2 | 构图稳，不跟目标转身 |
| 前两种都剪不出东西 | 下一轮自动换另一个 | 不用人肉试错 |

之前几轮拍出「树叶墙」「天花板」，根因不是运气差，是**一直用 ORBIT**。

另外：`LOCK` 是把镜头钉死在**世界坐标**上，目标一走开就变成对着空气——
它适合长镜固定机位，不适合跟拍，别拿它当跟拍用。

## 自动夜视

`film.mjs --auto` 会读 `get_world_info` 的 `is_dark_outside`：暗就开夜视，天亮自动还原。
夜视是干预，`cam_interventions.log` 有记录，成片里要标。

## 第十一轮：SHOULDER vs CINEMATIC 的 A/B（02:05 实测）

同一片针叶林、同一时刻，参数都取 4.5 格：

| 机位 | 站定时 | 走路时 |
|---|---|---|
| SHOULDER | 构图正常 | 人物被自己的模型挡住，只露出一条手臂 |
| CINEMATIC | 略近、无气泡、更干净 | 人物完整、背景有河岸和树 |

结论：默认 CINEMATIC，SHOULDER 只在需要「贴着背」的主观镜头时才用。

## 挖矿时的机位（02:50 实测）

| 机位 | 结果 |
|---|---|
| CINEMATIC（俯视） | 画面是「从上往下看一个坑」，帧间几乎不变 → 被判 static |
| BODY | 能看到人和周边（床、箱子、白桦林），帧间有变化 → 能剪出片子 |

原因：它垂直向下挖的时候，第三人称机位只能拍到坑壁；BODY 的机位更贴近身体，画面里才有动作。

## 相机 bug 的兜底：/cam tp（2026-11-02 实测）

**现象**：伙伴跑到 360 格外时，\`follow\`（牵引）不生效，机位卡在原地（311,56,276），
\`targetVisible=false\`。原因：牵引需要客户端能解析到目标实体，超出加载区就解析不到。

**兜底**：往聊天框注入 \`/cam tp\`（\`send-mc-command.ps1\`），机位立刻跳到目标旁（344,70,578），\`targetVisible=true\`。

**跨维度**：进下界后客户端在主世界看不见它，\`nether-watch.mjs\` 每 5 秒读维度，
一变到 \`the_nether\` 就自动 \`/cam tp\` → 录 20 秒。这条**还没实测成功**，能不能跨维度生效待验证。

## 高频观测：vitals.mjs（10 秒）

写 \`_photographer/vitals.jsonl\`：hp / 饥饿 / 位置 / 主手 / 背包占用 / 维度；
掉血≥2、换手、换维度、疑似死亡时打时间戳。用于给别的 AI 提供「事件 ±10 秒」的数值。

## 报「无进展」的四件套（学习线 AI 2026-11-02 定的口径）

1. 任务行（task_status 原文）
2. 10 秒粒度的 hp / hunger（vitals.jsonl）
3. 帧序列 + 时间码（take 名即起始时间）
4. 窗外 30 秒内的 tool_result 终态 —— **这一条摄影师给不了**

所以：缺第 4 条时只能标 INFERRED / UNKNOWN，不能写「卡死」。
反例教训：\`185040\` 静止 22.8 秒，看着像卡住，vitals 显示是在吃面包回血（REFUTED）。
