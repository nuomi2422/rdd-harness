# 摄影师（photographer/）

> 隔离工作树：`D:\rdd\worktrees\photographer`（分支 `photographer-film`）。
> 主工作树 `D:\rdd\harness\rdd-harness` 里还有别的 AI 在写 experiments/，本目录的改动不落地到那边。

## 这个 AI 干什么

看游戏里那个 AI 在干活 → 拍下来 → 挑出「有事发生」的段落剪成短片 → 删掉占地方的帧序列。

一句话：**不是记录全部，是记录能证明它会干活的那几段。**

## 三个脚本，一条链

| 脚本 | 作用 | 关键判据 |
|---|---|---|
| `film.mjs` | 一轮：检查取景 → 录 N 秒 → 调 cut → 记台账 → 调 patrol 清理 | 目标不可见/距离 > 24/已在录 → 直接不拍 |
| `cut.mjs` | 从一个 take 里挑变化段，切 clip 并拼成 `cut/highlight.mp4` | ffmpeg `scene` 分数 > 0.18；段间重叠合并；总长 ≤ 45s |
| `patrol.mjs` | 采样（`--once`）、常驻（`--loop 60`）、收摊（`--clean`，默认演练，`--apply` 才删） | 目标不可见 / 距离 > 24 / 贴脸 < 1.2 → 记 flags |

## 为什么这么切

- **变化 = 事件。** AI 在挖矿/打架/传送时画面剧烈变化；站着不动、界面挂着时几乎不动。
  用像素变化挑段，比「每 5 秒抽一帧」准得多，也不需要任何模型。
- **宁少不滥。** 总长封顶 45 秒、最多 6 段；挑不出就报错（`no-motion`），不硬凑。
- **删是不可逆的。** `--clean` 默认只打印计划；`film.mjs` 只在成片落盘后才调 `--apply`。

## 已知的坑（都是这轮踩的）

1. ffmpeg 的 `metadata=print:file=` **不能带盘符和空格**（会被当成 filter 选项），必须切到输出目录写相对名。
2. take 目录的 **mtime 不能当「新旧」**：往里写 `cut/` 就刷新了，刚剪完的会永远算新的。
   take 名字里自带开拍时间（`numencam_YYYYMMDD-HHMMSS`），用它。
3. 正则里的 `\d` 在模板字符串里会被吃成 `d` —— 写文件时用 `String.raw`，否则 `/(d{8})/` 永远匹配不上，
   结果是「所有 take 都算超期」直接删光。

## 还没做

- 事件语义：`cut.mjs` 会把段落对到 `patrol.jsonl` / `numencam.jsonl` 里最近的记录，但**必须拍摄当时有人在采样**，
  否则只能对到很远的旧记录（本轮就出现过 7.8 万秒的偏差）。
- 亮度判据：现在靠调用方看帧决定夜视，脚本不自动开（要开就得先能解码像素）。
- 遮挡：相机没有射线检测，贴墙/穿墙只能靠人眼看帧发现。

## 机位经验（这轮踩出来的）

| 场景 | 用什么 | 为什么 |
|---|---|---|
| 草原/开阔地 | ORBIT 6.5 格 / 高 2.2 | 能同时看到它和它在看的东西 |
| 室内/洞穴/窄通道 | BODY（第一人称） | 第三方机位会卡进方块，第一人称至少是它看见的画面 |
| 树林密集 | 先 BODY 试，不行再退 | ORBIT/SHOULDER 会被树叶糊满（连着两轮都这样） |

**BODY 的代价**：看得到它在看什么，看不到它本人。要「体现 agent 能力」的片子，两条腿都要有。

## 第三轮：机位到底该怎么选（读代码读出来的）

`MixinCamera` 里只有 **SHOULDER / CINEMATIC** 会走 `numencam$maxZoom()` —— 也就是原版那套
「8 个角点各打一条射线，被挡就把镜头拉近」。**ORBIT 是直接用 cos/sin 硬算坐标，完全不躲方块**，
所以它在树林/洞穴里必然穿模。

结论（已写进 `film.mjs --auto`）：

| 环境 | 机位 | 原因 |
|---|---|---|
| 密林 / 洞穴 / 室内（biome 含 forest/taiga/jungle/swamp 或 y<62） | **CINEMATIC** distance 6 / height 1.6 | 有射线拉近，贴墙也看得见人 |
| 开阔（草原、河谷、村庄空地） | ORBIT 6.5 / height 2.2 | 构图稳，不跟目标转身 |
| 前两种都剪不出东西 | 下一轮自动换另一个 | 不用人肉试错 |

之前几轮拍出「树叶墙」「天花板」，根因不是运气差，是**一直用 ORBIT**。

另外：`LOCK` 是把镜头钉死在**世界坐标**上，目标一走开就变成对着空气——
它适合长镜固定机位，不适合跟拍，别拿它当跟拍用。

## 自动夜视

## 相机 bug 的兜底：/cam tp（2026-11-02 实测）

## 「不动」的四分类（2026-11-02 与学习线 AI 对齐）

只凭画面/位置不动就报「卡死」是错的。现在分四类，前两类不是问题：

| 类 | 判据 | 谁能判 |
|---|---|---|
| 1 等定时器 | task_status 里有「挂着 N 个表」 | 摄影侧可判 |
| 2 只读轮询等待 | 身体不动 + 工具日志里 get_self_status 高频重复（例：11:39–11:42 共 56 次） | 需要工具日志 |
| 3 等救援 | 0 物品 + 危险地形 + 无可用动作 | 摄影侧可判（体征+画面） |
| 4 真卡死 | 任务说要做，位置与产出都不动，且无轮询/无定时器 | 要日志+画面合判 |

**教训**：11:39 那次我报了「卡住」，实际是第 2 类（等补给时的只读轮询）。以后只报 3 和 4，1/2 只记不报。

## 救援：rdd_admin_command 的真实约束（2026-11-02 踩出来的）

读 \`RddAdminCommandTool.java\` + 三次实测：

- 参数必须是 **\`command\` / \`stuck\` / \`confirm:true\`**（不是 \`reason\`；缺 \`stuck\` 会被拒）
- 白名单只看第一个词：\`give / setblock / fill / summon / gamemode / time / weather / tp\`
- 禁词：\`op deop ban kick stop kill difficulty gamerule @a @e @r\`
- 冷却 **60 秒**
- **\`execute\` 不在白名单** → 跨维度传送不能用 \`execute in <dim> run tp\`

跨维度救援的唯一可行姿势：
1. 用聊天注入把**机位玩家**（旁观者）tp 到目标点：\`/execute in minecraft:overworld run tp @s 355 65 599\`
2. 再用 \`rdd_admin_command\` 让同伴跟过来：\`{companion:"RDD", command:"tp @s RDD0", stuck:"…", confirm:true}\`
3. 前后各取一次 \`get_self_status\`，只有位置/维度真的变了才记 SUCCESS

失败会返回三种原文，要逐条记录，不能笼统写「完成」：
\`'stuck' reason required\` / \`'<x>' is not whitelisted\` / \`cooldown-60s\`

## 状态字段的唯一来源：patrol 的 \`state\`

从 2026-11-02 起，每条巡查采样都带 \`state\`：

| 值 | 含义 |
|---|---|
| \`working\` | 有任务、不是空闲 |
| \`idle\` | 身体空闲且没有定时器 |
| \`waiting\` | 身体空闲但挂着定时器（在等） |
| \`dead\` | 「她刚死了 / 复活途中」 |
| \`unknown\` | 拿不到任务文本 |

**分析脚本一律读 \`state\`，不要再自己写正则。** 我为此错过两次：
一次把 \`dead\` 算成 \`working\`（虚高 14 个采样），一次把「没采样到」说成「没派任务」。

## 观察者效应 2.0：跟拍会改变复活维度（2026-11-02 实测）

链条（UTC，逐条可查）：

| 时刻 | 事件 |
|---|---|
| 14:33:56 | 同伴在主世界 (304,66,272)，owner(RDDDev) 在 (304,66,276) |
| **14:34:24** | nether-watch 触发 \`/cam tp\` → **把 owner 送进下界** |
| 14:34:26 | 同伴下界 (61,39,33)，owner 同位置 |
| 14:34:48 | death59 |
| **14:34:56** | 同伴**复活在下界** (61,37,34)，背包 13→0 |

结论：**跟拍把 owner 搬进下界，同伴死亡后就近复活在下界**，而不是回主世界床。

因此：
1. \`nether-watch\` **默认不再把 owner 送进下界**，要拍必须显式 \`--allow-tp\`；
2. 规则从「死亡/复活期不动 owner」升级为「**owner 不能待在危险维度**」；
3. 任何跨维度跟拍，先确认「接受复活点可能改变」这个代价。

这比移动 owner 更隐蔽：位移看得见，**复活维度看不见**——只有把两边的日志按秒对齐才能发现。
