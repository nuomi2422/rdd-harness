## 0 · 先看顺序表（为什么必须这个顺序）

每一步都为下一步提供前提，**顺序错了会白跑**：

| 阶段 | 做什么 | 判据（做完能看到什么） | 为什么必须在这一步 |
|---|---|---|---|
| 0 | 环境体检 | 知道有没有 git/JDK/Node、有几个盘、有没有 GPU | 决定后面每个组件的来源与路径方案 |

| 2 | 工具链（git/JDK/Gradle/Node/ffmpeg/7z） | `java -version` / `node -v` / `gradle -v` 可用 | 阶段 1 的重写器本身要 Node；阶段 5 要 JDK+Gradle |

| 8 | 留痕（本文 + 09-更新日志 + 50-导航） | 门禁 `check-doc-freshness.js` 不报缺登记 | harness 自己的 Q9 门禁要求 |

## 1 · 阶段 0：环境体检（10 分钟）

```powershell
# 1) 有没有这些（没有就按 §3 装）
foreach ($t in 'git','node','java','javac','gradle','ffmpeg','7z') {
  "{0,-7} {1}" -f $t, (Get-Command $t -ErrorAction SilentlyContinue).Source
}
# 2) 盘符与空间（本例没有 E 盘，直接决定新布局）
Get-PSDrive -PSProvider FileSystem | Select-Object Name,@{n='FreeGB';e={[int]($_.Free/1GB)}}
# 3) 有没有独显（决定 Minecraft 能不能渲染）
Get-CimInstance Win32_VideoController | Select-Object Name,@{n='VRAM_MB';e={[int]($_.AdapterRAM/1MB)}}
(Get-CimInstance Win32_ComputerSystem).Model      # 本例：Alibaba Cloud ECS
# 4) PowerShell 版本与代码页（决定中文脚本怎么写）
$PSVersionTable.PSVersion; chcp
```

**本例结论**：无 git/JDK/Gradle/Node/ffmpeg；无 E 盘（C: 42G / D: 40G 空闲）；显卡只有 `AspDod/AspIdd` 虚拟显示驱动（**无 GPU**）；PowerShell 5.1，代码页 **936**。

> ⚠️ 坑 0-1：**「PATH 里有」和「当前进程看得到」是两回事**。你改完用户 PATH，已经开着的终端、以及宿主进程（如 DSH/Electron）仍然用旧环境。改完 PATH 要**重开终端**；用脚本调用时显式前缀 PATH 最稳。

## 2 · 阶段 1：仓库落地与路径重写（最容易翻车的一步）

新机统一到 `D:\rdd\`（干净路径名）：

### 2.2 三个「路径中枢」（只要改这三处，大部分东西就活了）

| 文件 | 侧 | 内容 |
|---|---|---|
| `workspace/rdd-selfcompile/scripts/config.ps1` | PowerShell | `$global:RDD_SC`：SC_ROOT / NUMMEN_REPO / GRADLE / JAVA_HOME / DOCS_* / 两个 MC 实例 / MONITOR_URL |
| `workspace/stager/core/stages.json` | Node | `docsRoot` / `docsOut` / `harnessRoot` / `gateExe` / `cmdPre·cmdPost` |
| `harness/rdd-harness/registry.json` | 机器可读真源 | `roots`：workspace / harness / docs / docsUnified / docsOut / numen / scripts / live / stageDocs |

### 2.3 重写器的四条硬规矩

自研脚本：`D:\rdd\tools\rewrite-paths.mjs`（可复用）。它踩过的坑就是规矩：

1. **两种转义形式都要处理**。`.ps1/.bat` 里是单反斜杠 `E:\...`；`.js/.json` 里是**双反斜杠** `E:\\...`。
   只写单反斜杠版本 → 所有 `.js/.json` 一个都没改（本例第一轮就漏了 498 处）。
   做法：基础表写单反斜杠，脚本自动派生「把每个 `\` 加倍」的变体，并按模式长度**降序**匹配（长的先替换）。
2. **保持编码**：读 UTF-8、写 UTF-8；**原来有 BOM 的保留 BOM**。
   PS 5.1 在代码页 936 下按 GBK 解码无 BOM 的中文 `.ps1` → 乱码，**行尾中文甚至能吞掉换行把下一行注释掉**。
   顺手做的一件好事：给「无 BOM + 含中文」的高危 `.ps1` 补 BOM。
3. **只动文本、只动该动的**：跳过 `.git/`、`node_modules/`、`build/`、`tools/`、`mc/`（否则会改到自己）。
4. **改完要检查残留**，并区分「操作性文件」与「归档文件」：
   本例残留 52 个文件全是归档类（`runtime/opencode-*.json` 里嵌的历史命令输出、自己声明「路径已失效」的 `implementation-plan.md`、`AcxPlugin.java` 里 `union:/E:/…` 这种格式示例）。

### 2.4 用 junction 让老路径「原样可用」

与其把 `gradle.properties` 里的 `E:\jdk21\jdk-21.0.11+10` 到处改，不如**造一个同名替身**：

```powershell
# 目录联接（不需要管理员）
cmd /c mklink /J "D:\rdd\tools\jdk21\jdk-21.0.11+10" "C:\Users\admin\AppData\Local\Programs\jdk-21.0.12.1+1"
cmd /c mklink /J "D:\rdd\workspace\gradle-9.2.0"      "C:\Users\admin\AppData\Local\Programs\gradle-9.2.0"
```

这样 `config.ps1` 里的 `JAVA_HOME` / `GRADLE` 只要把 `E:\jdk21` 换成 `D:\rdd\tools\jdk21`，
**版本号那一段不用动**，而且换 JDK 版本时只改联接。

### 2.5 补齐「不在 git 里」的部署副本

`.gitignore` 明确排除了 `rdd-selfcompile/instances/`、`mods/`、`config/*.json`、`rdd-monitor-publish-*/`、
`minecraft-numen/`、`mc-openclaw-controller/` 等。所以有几样必须从**别的仓**补：

| 7zr | standalone | 7-zip.org `/a/7zr.exe`（588KB） | 解 `.7z`（Mesa 之类）时需要 |

**Gradle wrapper 预热技巧**（让 `gradlew` 不再下 129MB，实测 1 秒起）：
Gradle 的 wrapper 缓存目录名是「distributionUrl 的 MD5 转 base36」：

```
~/.gradle/wrapper/dists/gradle-9.2.0-bin/11i5gvueggl8a5cioxuftxrik/
    ├─ gradle-9.2.0-bin.zip         ← 把你下的镜像包放进去
    ├─ gradle-9.2.0/                ← 解压好
    └─ gradle-9.2.0-bin.zip.ok      ← 建个空标记文件
```

> ⚠️ 坑 2-1：**`gradle.properties` 里写死 `org.gradle.java.home=E:\jdk21\...`** 是换机第一杀手——
> 构建直接报 `Java home supplied is invalid`，且报错发生在 Gradle 启动阶段，看起来像「Gradle 坏了」。
> 正解：删掉该行，让 JAVA_HOME/PATH 决定；「钉死 JDK 21」交给 `java_version=21` + foojay toolchain。
> 临时绕过：`gradlew "-Dorg.gradle.java.home=<路径>"`（命令行 `-D` 优先级高于项目 properties，实测有效）。

> ⚠️ 坑 2-2：git 全局身份默认是空的（新机器新装的 git）。提交前必须
> `git config --global user.name/user.email`，否则第一个 commit 就失败。

## 4 · 阶段 3：网络（决定能不能编译）

### 4.1 先判据，别猜

```powershell
Test-NetConnection maven.neoforged.net -Port 443 -InformationLevel Quiet   # 本例：False
Test-NetConnection libraries.minecraft.net  -Port 443 -InformationLevel Quiet   # True
Invoke-WebRequest https://piston-meta.mojang.com/mc/game/version_manifest_v2.json -Method Head  # 200
```

**本例结论**：Mojang 侧全通（MC 本体没问题），**只有 `maven.neoforged.net` 不可达**（HTTP/HTTPS 都超时）。

### 4.2 为什么必须是代理

试过的国内镜像**全部没有** NeoForge 制品（404）：

```
bmclapi2.bangbang93.com/neoforged/…      404
bmclapi2.bangbang93.com/maven/…          404
mirrors.nju.edu.cn/maven/neoforged/…     404
mirrors.zju.edu.cn/maven/neoforged/…     404
maven.aliyun.com/repository/neoforged/…  401（注意：这是它「没有这个 repo」的通用响应，不是有权限）
repo1.maven.org/maven2/net/neoforged/…   404（central 上没有 neoform-runtime）
```

### 4.3 怎么接

项目自带开关就是为这个场景留的：`config.ps1` 有 `RDD_GRADLE_PROXY`（注释写着「旧铁律：Gradle 强制走 7897」）。
本例用了更彻底的做法——本机起代理内核，**Gradle 全局走它**：

```powershell
# 1) 订阅 → 配置（Clash/mihomo 格式；本例订阅里 mixed-port: 7890）
node D:\rdd\tools\fetch-sub.mjs -f            # 取订阅、识别格式、存成 config.yaml
# 2) 起内核
D:\rdd\tools\mihomo\mihomo.exe -d D:\rdd\tools\mihomo -f D:\rdd\tools\mihomo\config.yaml
# 3) 验证「直连失败 vs 代理 200」再往下走
Invoke-WebRequest https://maven.neoforged.net/releases/net/neoforged/neoform-runtime/2.0.18/neoform-runtime-2.0.18.pom -Method Head -Proxy http://127.0.0.1:7890
# 4) Gradle 用 systemProp 形式写进用户级 gradle.properties
@"
systemProp.http.proxyHost=127.0.0.1
systemProp.http.proxyPort=7890
systemProp.https.proxyHost=127.0.0.1
systemProp.https.proxyPort=7890
systemProp.http.nonProxyHosts=localhost|127.0.0.1|[::1]
"@ | Add-Content $env:USERPROFILE\.gradle\gradle.properties
```

**Java 装 NeoForge 时要单独显式传参**（Java 不读 Gradle 的 systemProp）：

```powershell
java -Dhttp.proxyHost=127.0.0.1 -Dhttp.proxyPort=7890 `
     -Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=7890 `
     -jar neoforge-21.1.233-installer.jar --installClient D:\rdd\mc\store
```

> ⚠️ 坑 4-1：代理是**规则模式**（国内直连、国外走代理），所以开全局不会拖慢国内源；
> 但记得：**不用代理后要删掉那 6 行**，否则以后构建会莫名变慢或失败。
> ⚠️ 坑 4-2：代理订阅链接含 token，**别写进任何脚本文件**，用完轮换。

### 6.2 编译期我修掉的两个真 bug（已在源码留注释）

**坑 6-1 · `jarJar` 与 `jar{}` 重复打包 → 游戏崩 `ResolutionException`**
`neoforge-mod/build.gradle` 里既写了 `jarJar 'org.java-websocket:Java-WebSocket:1.5.4'`（正确），
又在 `jar { from { configurations.runtimeClasspath.filter{…}.collect{ zipTree(it) } } }` 里把
**Java-WebSocket 和 slf4j 扁平解包**进 jar 顶层 → 同一批类既在 `META-INF/jarjar/` 又在顶层 →
NeoForge 模块解析时「两个模块导出同一个包」。这就是文档里那句「375KB 那版会崩、147KB 干净版能用」的根因。
**修法：删掉 `jar{}` 那段**（slf4j 由 MC/NeoForge 提供）。

**坑 6-2 · 事件总线用错 → 客户端构造期崩**
`FMLClientSetupEvent` 与 `RegisterKeyMappingsEvent` 是 `IModBusEvent`，**必须注册到 mod bus**；
`ClientTickEvent.Post` 属于 **game bus**。而 NeoForge **禁止同一个对象注册到两条总线**：

```
java.lang.IllegalArgumentException: IModBusEvent events are not allowed on the common NeoForge bus!
```

**修法**：构造函数注入 `IEventBus modEventBus` 并 `modEventBus.register(this)`；
把 tick 处理拆成独立的 `TickHandler` 注册到 `NeoForge.EVENT_BUS`。

> ⚠️ 坑 6-3：javadoc 对中文注释会刷一堆「无效的输入: '<'」警告，**不影响构建**；
> 但 PowerShell 会把 stderr 当错误显示，导致 `${LASTEXITCODE}` 看起来是 1——**别被吓到，看 BUILD SUCCESSFUL**。

| # | 规则 | 不遵守的症状 |
|---|---|---|
| 1 | 库合并的 key **必须带 classifier**：`group:artifact:classifier` | 只用 `group:artifact` 会让 natives 覆盖 core → classpath 里没有 `lwjgl` 核心 jar → `Module org.lwjgl not found, required by org.lwjgl.natives` |
| 2 | 按 `rules` 过滤，**且要实现 feature rules**（`is_quick_play_singleplayer` 等） | 只看 `os` → 未替换的 `${quickPlaySingleplayer}` 被塞进参数、自己再追加一个 → `Found multiple arguments for option quickPlaySingleplayer` |
| 3 | `-DignoreList` 要写**真实的版本 jar 文件名** | 官方启动器把版本 jar 命名为 `<version_name>.jar`；我们的原版 jar 叫 `1.21.1.jar`，名字对不上 → `minecraft` 与 `_1._21._1` 双模块导出同包 → `ResolutionException` |
| 4 | NeoForge 的 classpath **已含 MC**，别再追加原版 client jar | 同上 |
| 5 | natives 只解 **x64**（按名字后缀排除 `-x86` / `-arm64`） | 各种 natives 的 rules 只写 "allow windows"，架构只在**名字**里；全解会把 x86 的 dll 覆盖上去 |

离线档案占位：`auth_player_name=RDDDev`、`auth_uuid=<固定 UUID>`、`auth_access_token=0`、`user_type=legacy`。

### 7.5 无 GPU 怎么办（本例答案：不用额外装东西）

先写一个 **GL 探针**再用结论说话（用 LWJGL，注意必须 `GL.createCapabilities()` 之后才能调 GL 函数，
否则会崩在 `lwjgl_opengl.dll` 让人误判成驱动问题）：

```java
glfwInit(); glfwWindowHint(GLFW_VISIBLE, GLFW_FALSE);
glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 3);
glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 2);
glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);
long w = glfwCreateWindow(320,240,"probe",0,0); glfwMakeContextCurrent(w);
GL.createCapabilities();
System.out.println(glGetString(GL_VERSION) + " / " + glGetString(GL_RENDERER));
```

本例结果（**没有独显**）：

```
GL_VERSION  = 4.2 (Core Profile) Mesa 24.0.1
GL_RENDERER = D3D12 (Microsoft Basic Render Driver)     ← 系统自带的 Mesa-on-D3D12(WARP)
```

MC 1.21 只要 3.2 Core → **直接满足，不需要 Mesa3D llvmpipe**。
（llvmpipe 仍可作为备选：`opengl32.dll` + `libgallium_wgl.dll` 放到 JVM 的 `bin` 或
 `-Djava.library.path` 指向的目录；注意 System32 里有同名 dll，优先级要靠前才行。）

## 9 · ★ 坑目录（症状 → 根因 → 修法）

按「最可能先撞上」排序。**加粗的是会让你浪费一小时以上的**。

### A. 环境 / 编码 / 工具调用

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| A1 | **`无法将"git"项识别为…`** | 机器根本没装 git | §3 装 MinGit，并加进 PATH |
| A2 | **改了用户 PATH，新开的这个终端还是找不到** | 已运行进程用旧环境快照 | 重开终端；宿主进程（DSH/Electron）要重启；脚本里显式前缀 PATH |
| A3 | **中文 `.ps1` 报奇怪的语法错 / 下一行像被注释掉** | UTF-8 **无 BOM** + 代码页 936 → 按 GBK 解码，行尾中文吞换行 | 给含中文的 `.ps1` **加 BOM**；`.bat` **只写 ASCII** |
| A4 | **内联 `node -e "…"` 各种 SyntaxError** | PowerShell 把 JSON 引号/`<`/`|` 吃掉 | 一律**写成脚本文件**，参数走 `@file` |
| A5 | `& ".\gradlew.bat"` 找不到 | 该工程只有 Unix `gradlew`，没有 `gradlew.bat` | 用外部 Gradle，或先 `gradle wrapper` |
| A6 | `.ps1` 被执行策略挡住 | Restricted/RemoteSigned | `powershell -ExecutionPolicy Bypass -File …`（注意 `pwsh` 可能不在 PATH，用 `$PSHOME` 或 `powershell.exe`） |
| A7 | `Start-Process` 报 `ArgumentList` 空/错 | 参数名撞上自动变量 `$args`；数组表达式写法错 | 参数改叫 `$argList`，先构造数组再传 |
| A8 | 后台任务随「上下文切换」消失 | 会话/上下文切换会带走后台作业句柄 | 长跑服务用 `Start-Process` **脱离**（detached）起，别只依赖作业 |
